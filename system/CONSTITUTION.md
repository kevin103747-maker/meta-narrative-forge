# system/CONSTITUTION.md

## 제1조: 단일 진실 공급원 (Single Source of Truth)
1. 시스템의 유일하고 절대적인 진실은 Git에 커밋된 파일들의 상태(\`git HEAD\`)뿐이다.
2. 에이전트는 이전 대화 세션의 기억이나 자체적인 가정을 진실로 간주해서는 안 되며, 반드시 명시적으로 전달된 파일의 내용에만 근거하여 사고한다.
3. Git에 커밋되지 않은 아이디어나 제안은 언제든 폐기되거나 수정될 수 있는 임시 상태(Draft)로 취급한다.

## 제2조: 원자적 트랜잭션과 명시적 작업 범위 (Atomic Transaction & Scoped Context)
1. 에이전트는 한 번의 작업에서 상호 의존적인 여러 파일을 넘나들며 수정할 수 있다.
2. **사전 선언의 의무:** 단, 작업을 시작하기 전 이번 턴에서 접근하고 수정할 대상 파일들의 목록(Scope)과 작업 순서(Dependency Chain)를 인간 감독관에게 명시적으로 선언해야 한다.
3. **트랜잭션의 원자성(All-or-Nothing):** 연쇄된 파일 수정은 하나의 묶음(Transaction)으로 취급되며, 그중 하나의 파일이라도 검증 스크립트(\`npm run audit\`)를 통과하지 못하면 해당 작업 전체를 롤백(폐기)하고 재작업한다.
4. 사전에 선언되지 않은 엉뚱한 외부 파일이나 무관한 모듈을 암묵적으로 건드리는 것은 엄격히 금지한다.

## 제3조: 결정적 규칙 우선 (Deterministic Over Generative)
1. 시공간 연산(거리, 시간, 좌표), 자원 수치(체력, 허기, 화폐), 조건 충족 여부는 LLM의 생성에 의존하지 않고, JavaScript/Python 코드 및 데이터베이스 쿼리를 통해 결정론적(0 토큰 비용)으로 판정한다.
2. 에이전트는 코드가 계산해 낸 결과값(출력 데이터)을 왜곡하거나 임의로 수정할 수 없으며, 오직 그 결과값을 서사적으로 해석하고 문장화하는 역할만을 수행한다.

## 제4조: 명시적 경로와 무손실 연결 (Explicit Pathing)
1. 모듈 간의 모든 참조는 암묵적인 텍스트 언급이 아닌, 디렉터리 기반의 명시적 경로(예: \`@/builders/world-graph-builder\`)를 통해서만 이루어져야 한다.
2. 존재하지 않는 경로나 미등록 모듈을 참조하는 것은 '빌드 에러'로 간주하며, 검증 스크립트(\`npm run audit\`)를 통과하기 전까지 시스템에 병합될 수 없다.

## 제5조: 인간 감독관의 승인권 (Human-in-the-Loop Authority)
1. 에이전트는 결정을 내리는 주체가 아니며, 구조화된 옵션(선택지)과 분석 결과를 제시하는 '조언자이자 작업자'이다.
2. 서사의 분기, 새로운 규칙의 채택, 최종 본문의 확정은 오직 인간 감독관의 명시적 승인을 거쳐 Git에 커밋됨으로써 효력을 갖는다.
